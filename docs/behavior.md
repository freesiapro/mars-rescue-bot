# 行为说明

本文说明机器人检测哪些消息、如何生成内容键、如何配对和提醒，以及排行榜和已知限制。配置与运行方式见 [配置](configuration.md) 和 [部署](deployment.md)；日志、`/hyw` 和数据保留见 [运维](operations.md)。

## 参与检测的内容

- **纯文本消息**：非频道转发、不含图片/视频/音频/文件、且不以 `/` 开头的文本消息。
- **纯链接消息**：整条消息只有一个或多个 http(s) 链接，链接之外只剩空白、标点或符号（emoji 也算符号）。`text` 中被 `url` 实体覆盖的文本、整条文本被 `text_link` 实体覆盖的消息也算纯链接；`text_link` 使用实体的 `url` 字段，锚文本不参与内容键。纯链接会正常统计和配对，使用独立的链接内容键，不套用文本的 10 字符下限。
- **富文本消息**：Bot API 10.1 的 `rich_message` 消息。机器人会先按块树提取去除格式后的纯文本（段落、标题、代码块、引用、列表、表格、详细信息、媒体 caption 等），再走与纯文本完全相同的归一化和去重规则。粗体、斜体、下划线、删除线、剧透、代码、链接、引用、自定义表情等格式本身不参与内容键。当前 telebot 版本能解析 `rich_message`，但不会把这类消息分派给 `OnText`/`OnMedia`（它们的 `text`/`caption`/媒体字段都为空，转发富文本也只命中 `OnForward`）。机器人用 telebot 自带的 `LongPoller` 包一层 `MiddlewarePoller`，在 Filter 里只给这类消息补一个空白占位 `text`，让直接和转发的富文本都走 telebot 的 `OnText`；正文提取仍优先 `RichMessage`，空白占位不会进入内容键或日志正文。
- **媒体消息**：非频道转发的图片、视频、动画、文件（文档），按 Telegram 的 `file_unique_id` 识别；同一文件被再次发送即视为重复。图片使用最大尺寸的 `file_unique_id`。不下载文件内容。
- **频道转发**：源聊天类型为频道的转发消息，按“原频道 + 原消息 ID”识别，同一个频道帖子被再次转发即视为重复。
- **其他转发**：转发 bot 或用户的消息，按归一化文本或媒体 `file_unique_id` 去重，和手打同样内容共用同一个内容键。

普通格式化消息的正文一直放在 `text`/`caption` 中，`entities`/`caption_entities` 只标记 UTF-16 范围，不会改变正文；因此同一条带格式和不带格式的内容会得到同一个内容键。媒体消息仍按 `file_unique_id` 去重，caption 不参与媒体键；富文本消息中的媒体块 caption 属于富文本内容，会随提取出的纯文本一起参与文本键。

## 内容键与归一化

文本会先做归一化再计算 HMAC-SHA256 内容键，数据库只保存键、不保存原文。归一化包括：Unicode NFKC（统一全角/半角）、去除零宽字符和变体选择符、折叠连续空白、ASCII 大小写折叠、去除标点/符号，以及 URL 规范化（小写 scheme/host、去 fragment、去默认端口、去末尾 `/`、移除 `utm_*`、`fbclid`、`gclid`、`spm`、`from`、`share_source` 等追踪参数，不访问短链）。因此 “Ｈｅｌｌｏ， MARS BOT！” 与 “hello mars bot” 会命中，而空白只折叠、不删除（`foo bar baz qux` 与 `foobarbazqux` 仍是不同内容）。

纯链接消息不走上面的文本归一化，改用独立的链接内容键。链接只做最保守的规范化：scheme 和 host 转小写。path、query、fragment、末尾 `/`、追踪参数、端口、`www` 前缀、`http` 与 `https` 的差异全部保留；拿不准的差异宁可视为不同链接，避免把用户眼中的不同链接误报为重复。多个链接按消息中的出现顺序用换行连接后计算 HMAC-SHA256，不排序、不去重：顺序不同、重复次数不同或链接集合不同都会得到不同键。链接原文和规范化后的链接都不会写入数据库或日志。

文本内容键带 `text:v2:` 版本前缀，链接内容键带 `link:v1:` 前缀，两者互不匹配。升级到该版本后，旧版用原始文本生成的键不会再与新键匹配，历史文本的重复计数会从升级后重新开始；旧记录仍保留在数据库中。此前以可见锚文本记录的 `text_link` 消息也不会与新链接键匹配，同一链接会从升级后重新开始计数。

## 不参与检测的内容

不参与文本去重的内容：只有 @ 提及的消息、归一化后有效字符（不含 URL、空白、标点）少于 10 个的文本、纯表情/符号、以 `/` 开头的命令（包括 `@bot` 形式）、归一化后所有字符都相同的刷屏（如“哈哈哈哈哈哈哈哈哈哈”“6666666666”，无论长度），以及机器人发送的消息。纯链接不在此列：它使用链接键参与统计和配对；链接之外还有字母或数字的消息仍按普通文本处理。富文本消息如果只剩分隔线、锚点等没有可见文本的块，会按未支持类型跳过。

“只有 @ 提及”指去掉 `mention` / `text_mention` 实体以及文本中形如 `@username` 的片段后，只剩空白、标点或符号（emoji 也算符号）。该判断对所有来源生效：普通消息、非频道转发、频道转发（`forward_origin.type=channel`）和富文本。带媒体（包括富文本媒体块）的消息不算纯 @，仍按原有规则处理，例如频道转发的图片即使 caption 只有 @，也按频道键记录。判断顺序是命令最先豁免，其次“只有 @”（在频道键、媒体键和 10 字符下限之前），再依次尝试频道键、媒体键和纯链接键，最后才套用 10 字符下限：否则 `@Bob @Alice` 会因为用户名恰好凑够字符被误记录，频道转发的纯 @ 也会先拿到 channel 键。含 @ 之外实际内容的消息仍按原规则处理；@ 部分继续像以前一样参与内容键（`@` 符号本身在归一化时被去掉），不会为了让内容键变短而剔除提及，因此 `@Alice 今天天气不错` 这类消息仍按完整文本判断。

## 配对方式

同一群聊中的同一内容（文本会忽略标点、大小写等差异）按出现顺序两两配对：

- 新内容出现：只记录，不提醒。
- 相同内容再次出现：与上一次未配对的出现配对，发送提醒；这一对结束。
- 之后再出现：重新开一对，只记录，不提醒。
- 再下一次出现：与新的一对配对，发送提醒；依此类推。

- 提醒文案不显示累计出现次数；配对只影响提醒，排行榜只统计重复出现（同一条内容在同一群的第一次出现不计入），累计次数不会清零。
- 每次提醒后，下一次出现重新开一对。
- 不区分发送者：同一个人重复发送同一内容同样会触发提醒。
- 同一内容连续刷屏（相邻两次消息 ID 相差 ≤5）视为同一波：只记录、不提醒，也不消耗配对位置；除该内容的首次出现外，后续流水仍计入排行榜。
- 每个提醒都会回复触发消息，并默认 @ 重复发送者；`/mars_mention off` 可关闭 @。
- 提醒会按内容使用“这条”“这张图”“这段视频”“这个动图”“这个文件”或“这条转发”，并显示首次记录者；文本匹配会忽略标点、大小写等差异。
- 首次记录时间在当天只显示“12:30”，其他日期显示“11-04 12:30”。频道转发里的首次记录者是第一次把原帖转发进群的人，不是原频道作者。
- 同一人重复发送时显示“这条你自己 … 就发过了 😂”，不再重复首发者。
- 升级前已有记录没有首发者信息时显示“这条群里早就有人发过了”，不显示时间和链接；有首发者但没有可用消息链接时，提醒省略“回现场”。
- 提醒中的原消息链接：公开群使用 `https://t.me/<username>/<msg_id>`，私有超级群使用 `https://t.me/c/<去掉 -100 的内部 ID>/<msg_id>`；普通群没有可用链接时省略“回现场”。
- 如果提醒因群冷却被抑制或发送失败，配对状态会回滚，下一次相同内容出现时仍可再次触发提醒。
- 被关闭检测的群、被加入忽略名单的用户，不会记录也不会回复。

## 排行榜

`/mars_rank` 按 `STATS_TZ` 时区统计每位用户在**当前群**的**重复出现次数**，最多展示前 10 名。同一条内容在同一群的第一次出现只记录、不计入；之后再出现（包括同一用户重复发送、自己重复、连续刷屏）都会计入。

- `/mars_rank` 或 `/mars_rank week`：本周（周一 00:00 起）的重复出现次数。
- `/mars_rank month`：本月（1 日 00:00 起）的重复出现次数。
- `/mars_rank all`：全部历史重复出现次数。

`/mars_me` 显示自己在当前群的本周、本月、累计重复出现次数，以及最近一次出现的时间。

周/月窗口按 `STATS_TZ` 的自然时间计算，再换算成绝对时间与数据库时间戳比较，不受服务器时区影响。

排行榜的累计次数只统计仍在保留期内的重复出现流水，保留策略见 [运维：数据保留与清理](operations.md#数据保留与清理)。

## 命令

管理员指 Telegram 群管理员或群主，权限通过 Telegram `getChatMember` 实时查询。

| 命令 | 权限 | 说明 |
| --- | --- | --- |
| `/start` | 所有人 | 查看机器人说明与命令列表 |
| `/mars_rank [week\|month\|all]` | 所有人（仅群聊） | 查看本周（默认）、本月或总火星指数榜 |
| `/mars_me` | 所有人（仅群聊） | 查看自己的本周、本月、累计次数与最近一次时间 |
| `/hyw` | 所有人（仅群聊，需回复消息） | 只读查询被回复消息是否被记录、内容类型、累计次数、首次/最近时间与可推导的决策 |
| `/mars_privacy` | 所有人（仅群聊） | 查看机器人保存的数据、用途与保留期 |
| `/mars_off` | 管理员 | 关闭本群检测：不记录、不回复 |
| `/mars_on` | 管理员 | 开启本群检测 |
| `/mars_status` | 管理员 | 查看本群状态、冷却秒数、@ 提醒开关、忽略人数 |
| `/mars_ignore` | 管理员 | 忽略某用户：回复该用户的消息，或传入数字用户 ID |
| `/mars_unignore` | 管理员 | 取消忽略：同样支持回复消息或数字用户 ID |
| `/mars_ignore_list` | 管理员 | 查看忽略名单，名单过长时仅展示前 100 人 |
| `/mars_cooldown <秒>` | 管理员 | 设置本群两条提醒之间的最小间隔，范围 0–86400；0 表示不冷却 |
| `/mars_mention on\|off` | 管理员 | 设置提醒中是否 @ 重复发送者，大小写不敏感 |

默认设置：检测开启、冷却 0 秒、@ 提醒开启。默认值只有在管理员修改设置后才会写入数据库。

`/hyw` 的完整说明和决策推导规则见 [运维：查询一条消息（/hyw）](operations.md#hyw)。

## 已知限制

- **文本匹配不做模糊搜索**：归一化只处理全半角、大小写、空白、标点、零宽字符和 URL 追踪参数；同义词、错别字、语序变化仍会被视为不同内容。
- **纯链接规范化很保守**：只统一 scheme/host 大小写。`http` 与 `https`、末尾 `/`、追踪参数、query 顺序、`www` 前缀等差异都会被视为不同链接，同一目标的不同写法可能分别计数。这是为了避免把用户眼中的不同链接误合并；需要更激进的合并时应单独评估。
- **仅覆盖文本、纯链接、四种媒体与频道转发**：文本、纯链接与图片/视频/动画/文件（含非频道转发），以及源为频道的转发会被去重；音频、语音、视频消息、贴纸、位置不参与。媒体去重只看 `file_unique_id`，重新压缩、截图、裁剪后的图片会被视为新内容；相册会拆成多条消息分别处理。
- **排行榜按重复出现计**：同一条内容在同一群的第一次出现只记录、不计入排行榜；之后的每次出现都会计入，包括同一用户反复发送同一内容和自己重复。
- **冷却仅单实例**：冷却保存在进程内存中，重启后清零，也不会在多实例之间共享。
- **单实例 SQLite**：数据库连接数被限制为 1，设计为单实例部署；多个实例共享同一个 SQLite 文件不受支持。
- **忽略名单不支持 @username**：`/mars_ignore` 与 `/mars_unignore` 只接受“回复目标消息”或数字用户 ID。
- 私聊消息会被忽略；匿名管理员或频道身份发送、缺少发送者信息的消息会被跳过。
- 以 `/` 开头的文本不会进入去重流程。
