# 运维

本文说明机器人保存的数据、运行日志与去重决策日志、`/hyw` 查询、数据保留清理和常见排查。检测规则见 [行为说明](behavior.md)，环境变量见 [配置](configuration.md)，部署与备份见 [部署](deployment.md)。

## 隐私与数据

数据库（SQLite）中保存的内容（群内可发送 `/mars_privacy` 查看）：

- **文本内容键**：`HMAC-SHA256(DEDUP_SECRET, 归一化后的文本)` 的十六进制结果，不保存原文或归一化后的文本。富文本消息先提取去除格式后的纯文本，再按同一流程计算。未设置 `DEDUP_SECRET` 时回退使用 `BOT_TOKEN` 作为密钥。
- **链接内容键**：纯链接消息使用 `link:v1:` 前缀。链接按出现顺序、每个只做 scheme/host 小写后，以换行连接，再计算 `HMAC-SHA256(DEDUP_SECRET, ...)`；数据库和日志都不保存链接原文。
- **Telegram ID**：群 ID、用户 ID、消息 ID；频道转发的内容键中还包含原频道 ID 与原消息 ID；媒体内容键中包含 `file_unique_id`。内容记录还保存最近一次出现的消息 ID，仅用于识别连续刷屏。每条出现流水还保存发送者 ID，以及该消息的 Telegram `date`（`forward_logs.message_unix`，Unix 秒，可空）。升级前的旧流水此列为 NULL。只存数字，不存原文，用来判断后来的转发是不是本群这一条。
- **排行榜数据**：只保存用户 ID 与出现流水（用于计算重复出现次数，首次出现不计入）。姓名和 username 不写入数据库；展示排行榜、首发者时使用进程内缓存，未命中再调用 Telegram `getChatMember`，查询失败显示“用户 &lt;id&gt;”。升级时会清空旧版本 `user_stats` 中已经保存的 `username`/`first_name`，列本身保留以兼容旧数据库。
- **群设置**：群 ID、开关、冷却秒数、操作者用户 ID。
- **忽略名单**：群 ID、被忽略用户 ID、操作者用户 ID、添加时间。
- **时间戳**：记录的创建与更新时间。

不保存：消息原文、链接原文、媒体文件内容、文件下载链接。媒体消息只保存不可逆的 `file_unique_id` 用于去重；纯链接消息只保存 HMAC 内容键。机器人不保存原始消息 JSON；`present_fields` / `rich_block_types` 来自 telebot 已解析的 `Message` 结构，只包含字段名和块类型，不包含字段值或正文。

运行日志以 JSON 输出到 stdout，包含群 ID、用户 ID、消息 ID、消息类型等元数据，不包含用户名或消息正文。`收到消息` 日志对转发额外输出 `forward_origin`（`user`、`chat`、`channel`、`hidden_user` 或空）、`has_sender_name`（布尔值，仅表示有没有姓名，不输出姓名本身）；有原发送者 ID 时输出 `origin_user_id`，有原发送时间时输出 `origin_date`（Unix 秒）。

## 去重决策日志

每条经过去重处理的消息都会额外输出一条 INFO 日志，消息固定为 `dedup decision`。它与原有的 `收到消息` 日志并列：前者说明检测结果，后者记录收到的更新，每条消息各一条，不重复输出。字段只有：

| 字段 | 说明 |
| --- | --- |
| `chat_id` | 群 ID；缺少 chat 时为 0 |
| `message_id` | 消息 ID；缺少消息时为 0 |
| `msg_type` | `channel_forward`、`rich_message`、`text`、`link`、`photo`、`video`、`animation`、`document`、`audio`、`sticker`、`voice`、`location`、`contact`、`caption` 或 `unknown`；频道转发优先于原始内容类型 |
| `decision` | 本次处理结果，取值见下表 |
| `user_id` | 发送者 ID，与 `收到消息` 日志一致；缺少发送者时为 0 |
| `origin_type` | 可选。消息带新版 `forward_origin` 时输出来源类型：`user`、`chat`、`channel` 或 `hidden_user` |
| `origin_date` | 可选。随 `origin_type` 输出：转发来源里的原发送时间（Unix 秒）；没有时为 0 |
| `reason` | 可选。引用豁免的判定结果：命中时是豁免原因，未命中时是没豁免的原因，取值见下文 |
| `key_hash` | 可选。内容键的 8 位十六进制短指纹；没有内容键时省略 |
| `present_fields` | 可选。仅 `no_content` / `unsupported_type` 时输出：消息中非空顶层字段名（排序、去重；`null`、空字符串、空数组/对象、`false`、`0` 不计），不包含字段值和正文。使用 telebot 解析后的 `Message` 结构，看不到 telebot 未建模的字段；富文本路由用的空白占位 `text` 会被排除 |
| `rich_block_types` | 可选。仅当消息带 `rich_message` 且决策为 `no_content` / `unsupported_type` 时输出：块树中出现过的 `type` 名称（排序、去重，含嵌套块），不包含任何文本 |

`key_hash` 对文本和链接直接使用现有 HMAC-SHA256 内容键的前 8 位；媒体和频道键本身不是 HMAC（包含 `file_unique_id` 或原频道 ID），因此使用 `HMAC-SHA256(DEDUP_SECRET, 完整内容键)` 后再取前 8 位，避免明文暴露这些标识。日志永远不包含完整内容键、消息正文、caption、用户名或姓名。

| `decision` | 产生分支 |
| --- | --- |
| `alerted` | 本次出现完成配对，且提醒发送成功 |
| `paired_silent` | 新内容首次记录，或本次出现进入等待配对、不提醒 |
| `adjacent_repeat_exempt` | 与上一次出现的 `message_id` 相差不超过 5，按连续刷屏只写流水、不提醒；除首次出现外仍计入排行榜 |
| `short_text_skipped` | 归一化后内容分不足 10 分的文本（汉字、平假名、片假名、韩文每字 1 分，拉丁单词每个 2 分，其他文字每字母 1 分；URL 不计分）；纯链接走链接键，不会命中该分支 |
| `repeated_char_skipped` | 归一化后所有字符都相同，且内容分已达到下限（如“哈哈哈哈哈哈哈哈哈哈”）；纯数字或纯字母的长串会先因内容分不足命中 `short_text_skipped` |
| `mention_only` | 去掉 @ 提及（`mention` / `text_mention` 实体或文本中的 `@username`）后只剩空白、标点或符号；对所有来源（含频道转发）生效，不检测、不记录、不参与配对 |
| `citation_skipped` | 引用豁免：用户转发的原作者和时间对上本群某次已记录出现（容差 2 秒）；`sender_chat` 为本群且时间对得上，或没有可比较的时间；隐藏来源的转发对上带消息时间的流水（时间完全相等），或对上插入时间在原消息后 60 秒内且发送者当前显示名一致的旧流水；以及回复的内容键与被回复消息相同。不记录、不提醒、不进排行。频道转发（含自动转发）不会命中 |
| `bot_ignored` | 发送者本身是 bot |
| `forward_from_bot_ignored` | 保留值，当前不可达：只有发送者是 bot 才会被忽略。人类转发 bot 内容时与其他用户转发一样，按原作者和时间判断 |
| `ignored_user` | 发送者在忽略名单中 |
| `disabled_chat` | 本群检测已关闭 |
| `cooldown_suppressed` | 配对提醒被群冷却抑制，配对状态已回滚 |
| `send_failed_rolled_back` | 配对提醒发送失败，配对状态已回滚 |
| `no_content` | 没有可检测内容：空文本、纯空白、归一化后为空的纯表情/符号，或支持的媒体缺少 `file_unique_id`。日志会附带 `present_fields` |
| `private_chat` | 私聊消息，直接忽略 |
| `command` | 以 `/` 开头的命令文本 |
| `unsupported_type` | 音频、贴纸、语音、位置、联系人，或没有任何可提取文本的富文本消息等未参与检测的内容。日志会附带 `present_fields`，富文本消息还会附带 `rich_block_types` |
| `no_message` / `no_chat` / `no_sender` | Telegram 更新缺少消息、chat 或发送者，安全跳过 |
| `processing_error` | 读取设置、忽略名单或写入去重数据时出错；原有错误日志仍会输出 |

`reason` 在消息进入引用判断时出现，普通消息通常没有。命中豁免时取值 `author_time`（用户来源：原作者 ID 和时间对上）、`member_fallback`（用户来源：旧流水没有消息时间，原作者仍在本群）、`chat_time`（本群来源：时间对上）、`chat_no_timed_log`（本群来源：没有可比较的时间）、`hidden_exact_time`（隐藏来源：消息时间完全相等）、`hidden_legacy_window`（隐藏来源：旧流水插入时间在窗口内且显示名一致）、`reply_same_key`（回复的内容与被回复消息相同，不要求是转发）。未命中时取值 `no_record`、`no_timed_match`、`member_lookup_failed`、`not_in_group`、`hidden_name_mismatch`、`hidden_outside_window` 或 `origin_not_candidate`。成员或姓名查询失败时还会输出一条 WARN 日志，包含 `chat_id`、`user_id` 和 `error`，不包含姓名。

## 数据保留与清理

数据保留：默认保留 **180 天**，可通过 `DATA_RETENTION_DAYS` 调整。程序启动时执行一次清理，之后每 24 小时执行一次：

- 删除 `created_at` 早于保留期的 `forward_logs`；
- 先删除过期记录残留的流水，再删除 `updated_at` 早于保留期的 `forward_records`，避免孤儿流水；
- 删除不再被任何保留期流水引用的 `user_stats` 行（该表只含用户 ID）。

清理按批次执行，不会一次性锁住数据库。`/mars_rank all` 和 `/mars_me` 的“累计”只统计仍在保留期内的重复出现流水。

## 查询一条消息（/hyw）

在群里回复一条消息，再发送 `/hyw`（也支持 `/hyw@botname`）。机器人会回复被查询的那条消息，说明：

- 这条内容在本群有没有记录；
- 一共出现几次（含第一次，不是火星次数；次数含已被保留期清掉明细后仍留在累计里的历史次数）；
- 最早和最近一次出现的时间，格式与提醒一致：当天 `12:30`，其他日期 `11-03 12:30`；
- 就现有记录能够确定时，这次有没有发出提醒，以及为什么没有。

用户看到的是完整句子，不包含内容键、短码、HMAC、内部字段名或决策代码。没有回复就发送时，提示先回复要查询的消息。私聊会说明无法查询。

这是**只读**查询：不会新增/修改 `forward_records`、`forward_logs`、`user_stats`，不会改变配对状态、最近消息 ID 或任何设置，也不会发送提醒。查询只限当前群；其他群记录不会命中。`/hyw` 自身是命令，沿用命令豁免：不记录、不计数，只产生一条 `decision=command` 的决策日志。

数据库没有逐条保存“这条消息当时有没有提醒”，只保存记录、出现流水和当前配对状态。回复只根据这些证据下结论。记录还在，也不表示这次一定发出了提醒：

| 用户看到的 | 依据 |
| --- | --- |
| `这是第一次出现，只记录，没有提醒。` | 被查询的消息 ID 等于记录的 `first_target_msg_id` |
| `和上一条挨得很近，所以没有提醒。` | 流水里能找到上一条，且两条消息 ID 相差 0–5 |
| `这次发出了提醒。` | 它是最近一次出现（`last_occurrence_msg_id`，缺失时回退到最后一条流水），且记录当前没有待配对（`pending_pair=false`；旧行按 `ForwardCount` 奇偶推导） |
| `这条消息的单次记录已经不在了，没法判断当时有没有提醒。` | 内容记录还在，但这条消息已经不在流水里 |
| `更早的出现已经不在记录里，没法判断这次有没有提醒。` | 这条是目前最早的一条流水，前面的流水已经不在 |
| `后面又出现过同样的内容，没法判断这次有没有提醒。` | 它不是最近一次出现 |
| `这次有没有发出提醒，现有记录看不出来。…` | 它是最近一次，但当前仍可能只做了记录、被提醒间隔拦住，或发送失败 |

补充说明：

- 本群没有记录时，回复说明可能当时没有检测到，或记录已超过保留期。不会把这种情况说成“第一次出现”；第一次出现本身会被记下。
- 同样的内容有记录、但这条消息本身不在其中时，会说明不能据此判断这条有没有被检测到或提醒。
- 升级前已有记录没有 `last_occurrence_msg_id`；升级后的第一次出现仍按普通配对分支处理，但流水里前后消息 ID 可能相邻，因此 `/hyw` 可能把它显示为「和上一条挨得很近，所以没有提醒。」这是查询侧的证据限制，不影响当时的实际配对。
- 没有回复消息、在私聊使用、回复 bot 消息，或回复的是命令、只有 @ 的消息、过短文本、同一个字刷屏、没有可记录的内容、语音、贴纸等不查重的内容时，机器人会用一句话说明。这些回复不列出消息字段名。

## 排障

- **群里收不到普通消息**：检查 BotFather 隐私模式是否已关闭，修改后是否把 Bot 移出群再重新加入；或把 Bot 设为管理员。见 [配置：BotFather 注意事项](configuration.md#botfather-注意事项)。
- **只有命令有反应**：同上，通常是隐私模式仍开启。
- **命令没有反应**：确认是在群聊中使用；管理员命令要求操作者是群管理员或群主，权限通过 `getChatMember` 实时查询。私聊消息会被忽略。
- **重复内容没有提醒**：检查本群是否被 `/mars_off` 关闭、发送者是否在忽略名单、是否处于冷却期、是否属于相邻消息 ID 相差 ≤5 的连续刷屏，或内容本身是否参与检测。转发本群已记下的那一条，或回复时贴出同一内容，不会记录。可用 `/hyw` 回复该消息查看记录和这次有没有提醒，或查看 `dedup decision` 日志中的 `decision`。
- **`/hyw` 说没法判断或看不出来**：这是查询侧证据不够，不代表当时没有检测，也不代表记录存在就一定发出了提醒。具体原因见上面的说明。
- **数据库报错或锁住**：确认只有一个 Bot 实例在写同一个 SQLite 文件；数据库按单实例、单连接设计。见 [行为说明：已知限制](behavior.md#已知限制)。
- **时间或排行榜周期不对**：检查 `STATS_TZ`；非法时区会回退。周/月窗口按该时区的自然时间计算，再换算成绝对时间与数据库时间戳比较，不受服务器时区影响。见 [配置：环境变量](configuration.md#环境变量)。
- **日志在哪里**：运行日志以 JSON 输出到 stdout；Docker 使用 `docker compose logs -f` 查看。
