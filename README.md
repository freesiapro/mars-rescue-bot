# 火星救援 Bot

一个用 Go 编写的 Telegram 群聊机器人：当群里反复出现同一内容时，它会发送一条“火星救援”提醒，并把重复发送者计入火星指数排行榜。

机器人会忽略私聊消息，目标使用场景是群聊。

## 检测规则

### 参与检测的内容

- **纯文本消息**：非频道转发、不含图片/视频/音频/文件、且不以 `/` 开头的文本消息。
- **富文本消息**：Bot API 10.1 的 `rich_message` 消息。机器人会先按块树提取去除格式后的纯文本（段落、标题、代码块、引用、列表、表格、详细信息、媒体 caption 等），再走与纯文本完全相同的归一化和去重规则。粗体、斜体、下划线、删除线、剧透、代码、链接、引用、自定义表情等格式本身不参与内容键。
- **媒体消息**：非频道转发的图片、视频、动画、文件（文档），按 Telegram 的 `file_unique_id` 识别；同一文件被再次发送即视为重复。图片使用最大尺寸的 `file_unique_id`。不下载文件内容。
- **频道转发**：源聊天类型为频道的转发消息，按“原频道 + 原消息 ID”识别，同一个频道帖子被再次转发即视为重复。
- **其他转发**：转发 bot 或用户的消息，按归一化文本或媒体 `file_unique_id` 去重，和手打同样内容共用同一个内容键。

普通格式化消息的正文一直放在 `text`/`caption` 中，`entities`/`caption_entities` 只标记 UTF-16 范围，不会改变正文；因此同一条带格式和不带格式的内容会得到同一个内容键。媒体消息仍按 `file_unique_id` 去重，caption 不参与媒体键；富文本消息中的媒体块 caption 属于富文本内容，会随提取出的纯文本一起参与文本键。

文本会先做归一化再计算 HMAC-SHA256 内容键，数据库只保存键、不保存原文。归一化包括：Unicode NFKC（统一全角/半角）、去除零宽字符和变体选择符、折叠连续空白、ASCII 大小写折叠、去除标点/符号，以及 URL 规范化（小写 scheme/host、去 fragment、去默认端口、去末尾 `/`、移除 `utm_*`、`fbclid`、`gclid`、`spm`、`from`、`share_source` 等追踪参数，不访问短链）。因此 “Ｈｅｌｌｏ， MARS！” 与 “hello mars” 会命中，而空白只折叠、不删除（`foo bar` 与 `foobar` 仍是不同内容）。

不参与文本去重的内容：归一化后有效字符（不含 URL、空白、标点）少于 4 个、纯 URL、纯表情/符号、以 `/` 开头的命令（包括 `@bot` 形式）、归一化后所有字符都相同的刷屏（如“哈哈哈哈”“666666”，无论长度），以及机器人发送的消息。富文本消息如果只剩分隔线、锚点等没有可见文本的块，会按未支持类型跳过。

内容键带 `text:v2:` 版本前缀。升级到该版本后，旧版用原始文本生成的键不会再与新键匹配，历史文本的重复计数会从升级后重新开始；旧记录仍保留在数据库中。

### 配对方式

同一群聊中的同一内容（文本会忽略标点、大小写等差异）按出现顺序两两配对：

- 新内容出现：只记录，不提醒。
- 相同内容再次出现：与上一次未配对的出现配对，发送提醒；这一对结束。
- 之后再出现：重新开一对，只记录，不提醒。
- 再下一次出现：与新的一对配对，发送提醒；依此类推。

- 提醒文案不显示累计出现次数；配对只影响提醒，排行榜仍按每一次出现计数，累计次数不会清零。
- 每次提醒后，下一次出现重新开一对。
- 不区分发送者：同一个人重复发送同一内容同样会触发提醒。
- 同一内容连续刷屏（相邻两次消息 ID 相差 ≤5）视为同一波：只记录、计入排行榜，不提醒，也不消耗配对位置。
- 每个提醒都会回复触发消息，并默认 @ 重复发送者；`/mars_mention off` 可关闭 @。
- 提醒会按内容使用“这条”“这张图”“这段视频”“这个动图”“这个文件”或“这条转发”，并显示首次记录者；文本匹配会忽略标点、大小写等差异。
- 首次记录时间在当天只显示“12:30”，其他日期显示“11-04 12:30”。频道转发里的首次记录者是第一次把原帖转发进群的人，不是原频道作者。
- 同一人重复发送时显示“这条你自己 … 就发过了 😂”，不再重复首发者。
- 升级前已有记录没有首发者信息时显示“这条群里早就有人发过了”，不显示时间和链接；有首发者但没有可用消息链接时，提醒省略“回现场”。
- 提醒中的原消息链接：公开群使用 `https://t.me/<username>/<msg_id>`，私有超级群使用 `https://t.me/c/<去掉 -100 的内部 ID>/<msg_id>`；普通群没有可用链接时省略“回现场”。
- 如果提醒因群冷却被抑制或发送失败，配对状态会回滚，下一次相同内容出现时仍可再次触发提醒。
- 被关闭检测的群、被加入忽略名单的用户，不会记录也不会回复。

### 排行榜

`/mars_rank` 按 `STATS_TZ` 时区统计每位用户**每次出现**的次数，最多展示前 10 名。每一次出现、同一用户重复发送同一内容、自己重复，都会计入。

- `/mars_rank` 或 `/mars_rank week`：本周（周一 00:00 起）。
- `/mars_rank month`：本月（1 日 00:00 起）。
- `/mars_rank all`：全部历史。

`/mars_me` 显示自己在当前群的本周、本月、累计出现次数，以及最近一次出现的时间。

### 查询一条消息（`/hyw`）

在群里**回复**任意一条消息，再发送 `/hyw`（也支持 `/hyw@botname`），机器人会回复被查询的消息：

- 有没有被火星小本本记上；
- 内容类型：文本、图片、视频、动图、文件或频道转发；
- 8 位内容指纹（就是决策日志里的 `key_hash`；不显示完整内容键、`file_unique_id`、频道 ID 或消息原文）；
- `ForwardCount` 累计出现次数（包含已被保留期清理掉流水的历史次数）；
- 首次和最近一次出现的时间，格式与提醒一致：当天 `12:30`，其他日期 `11-03 12:30`。

这是**只读**查询：不会新增/修改 `forward_records`、`forward_logs`、`user_stats`，不会改变配对状态、最近消息 ID 或任何设置，也不会发送提醒。查询只限当前群；其他群记录不会命中。`/hyw` 自身是命令，沿用命令豁免：不记录、不计数，只产生一条 `decision=command` 的决策日志。

数据库没有逐条保存“这条消息当时是什么决策”，只保存记录、出现流水和当前配对状态。因此回复里的“决策”只根据现有证据推导，推导不出来的会直接写“没法确定”：

| 显示 | 推导规则 |
| --- | --- |
| `paired_silent（第一次见，先记下）` | 被查询的消息 ID 等于记录的 `first_target_msg_id`，一定是首次出现 |
| `adjacent_repeat_exempt（跟上一波连着刷，没打扰）` | 能在流水里找到它的上一条，且两条消息 ID 相差 0–5 |
| `alerted（这次提醒发出去了）` | 它是最近一次出现（`last_occurrence_msg_id`，缺失时回退到最后一条流水），且记录当前没有待配对（`pending_pair=false`；旧行按 `ForwardCount` 奇偶推导） |
| `没法确定（...）` | 流水里找不到这条、它不是最近一次、或最近一次仍有待配对。后两种无法区分静默配对、冷却抑制和发送失败回滚 |

补充说明：

- 流水超过保留期被清理后，旧消息可能只剩累计次数，无法再定位单条消息，此时会提示流水已过保留期。
- 升级前已有记录没有 `last_occurrence_msg_id`；升级后的第一次出现仍按普通配对分支处理，但流水里前后消息 ID 可能相邻，因此 `/hyw` 可能把它显示为 `adjacent_repeat_exempt`。这是查询侧的证据限制，不影响当时的实际配对。
- 没有回复消息、在私聊使用、回复 bot 消息，或回复的是命令、过短文本、纯复读字符、空内容、音频等不参与去重的内容时，机器人会给出简短说明或用法提示。

## 命令

管理员指 Telegram 群管理员或群主，权限通过 Telegram `getChatMember` 实时查询。

| 命令 | 权限 | 说明 |
| --- | --- | --- |
| `/start` | 所有人 | 查看机器人说明与命令列表 |
| `/mars_rank [week\|month\|all]` | 所有人（仅群聊） | 查看本周（默认）、本月或总火星指数榜 |
| `/mars_me` | 所有人（仅群聊） | 查看自己的本周、本月、累计次数与最近一次时间 |
| `/hyw` | 所有人（仅群聊，需回复消息） | 只读查询被回复消息是否被记录、内容类型、累计次数、首次/最近时间与可推导的决策 |
| `/mars_privacy` | 所有人（仅群聊） | 查看机器人保存的数据、用途与保留期 |
| `/mars_off` | 管理员 | 关闭本群检测：不记录、不回复 |
| `/mars_on` | 管理员 | 开启本群检测 |
| `/mars_status` | 管理员 | 查看本群状态、冷却秒数、@ 提醒开关、忽略人数 |
| `/mars_ignore` | 管理员 | 忽略某用户：回复该用户的消息，或传入数字用户 ID |
| `/mars_unignore` | 管理员 | 取消忽略：同样支持回复消息或数字用户 ID |
| `/mars_ignore_list` | 管理员 | 查看忽略名单，名单过长时仅展示前 100 人 |
| `/mars_cooldown <秒>` | 管理员 | 设置本群两条提醒之间的最小间隔，范围 0–86400；0 表示不冷却 |
| `/mars_mention on\|off` | 管理员 | 设置提醒中是否 @ 重复发送者，大小写不敏感 |

默认设置：检测开启、冷却 0 秒、@ 提醒开启。默认值只有在管理员修改设置后才会写入数据库。

## 隐私与数据

数据库（SQLite）中保存的内容（群内可发送 `/mars_privacy` 查看）：

- **文本内容键**：`HMAC-SHA256(DEDUP_SECRET, 归一化后的文本)` 的十六进制结果，不保存原文或归一化后的文本。富文本消息先提取去除格式后的纯文本，再按同一流程计算。未设置 `DEDUP_SECRET` 时回退使用 `BOT_TOKEN` 作为密钥。
- **Telegram ID**：群 ID、用户 ID、消息 ID；频道转发的内容键中还包含原频道 ID 与原消息 ID；媒体内容键中包含 `file_unique_id`。内容记录还保存最近一次出现的消息 ID，仅用于识别连续刷屏。
- **排行榜数据**：只保存用户 ID 与出现次数。姓名和 username 不写入数据库；展示排行榜、首发者时使用进程内缓存，未命中再调用 Telegram `getChatMember`，查询失败显示“用户 &lt;id&gt;”。升级时会清空旧版本 `user_stats` 中已经保存的 `username`/`first_name`，列本身保留以兼容旧数据库。
- **群设置**：群 ID、开关、冷却秒数、操作者用户 ID。
- **忽略名单**：群 ID、被忽略用户 ID、操作者用户 ID、添加时间。
- **时间戳**：记录的创建与更新时间。

不保存：消息原文、媒体文件内容、文件下载链接。媒体消息只保存不可逆的 `file_unique_id` 用于去重。

运行日志以 JSON 输出到 stdout，包含群 ID、用户 ID、消息 ID、消息类型等元数据，不包含用户名或消息正文。

### 去重决策日志

每条经过去重处理的消息都会额外输出一条 INFO 日志，消息固定为 `dedup decision`。它与原有的 `收到消息` 日志并列：前者说明检测结果，后者记录收到的更新，每条消息各一条，不重复输出。字段只有：

| 字段 | 说明 |
| --- | --- |
| `chat_id` | 群 ID；缺少 chat 时为 0 |
| `message_id` | 消息 ID；缺少消息时为 0 |
| `msg_type` | `channel_forward`、`rich_message`、`text`、`photo`、`video`、`animation`、`document`、`audio`、`sticker`、`voice`、`location`、`contact`、`caption` 或 `unknown`；频道转发优先于原始内容类型 |
| `decision` | 本次处理结果，取值见下表 |
| `user_id` | 发送者 ID，与 `收到消息` 日志一致；缺少发送者时为 0 |
| `key_hash` | 可选。内容键的 8 位十六进制短指纹；没有内容键时省略 |

`key_hash` 对文本直接使用现有 HMAC-SHA256 内容键的前 8 位；媒体和频道键本身不是 HMAC（包含 `file_unique_id` 或原频道 ID），因此使用 `HMAC-SHA256(DEDUP_SECRET, 完整内容键)` 后再取前 8 位，避免明文暴露这些标识。日志永远不包含完整内容键、消息正文、caption、用户名或姓名。

| `decision` | 产生分支 |
| --- | --- |
| `alerted` | 本次出现完成配对，且提醒发送成功 |
| `paired_silent` | 新内容首次记录，或本次出现进入等待配对、不提醒 |
| `adjacent_repeat_exempt` | 与上一次出现的 `message_id` 相差不超过 5，按连续刷屏只计数、不提醒 |
| `short_text_skipped` | 归一化后有效字符少于 4 个、纯 URL 或纯表情/符号 |
| `repeated_char_skipped` | 归一化后所有字符都相同（如“哈哈哈哈”“666666”） |
| `bot_ignored` | 发送者本身是 bot |
| `forward_from_bot_ignored` | 保留值，当前不可达：只有发送者是 bot 才会被忽略；人类转发 bot 内容仍按普通内容去重 |
| `ignored_user` | 发送者在忽略名单中 |
| `disabled_chat` | 本群检测已关闭 |
| `cooldown_suppressed` | 配对提醒被群冷却抑制，配对状态已回滚 |
| `send_failed_rolled_back` | 配对提醒发送失败，配对状态已回滚 |
| `no_content` | 没有可检测内容：空文本、纯空白，或支持的媒体缺少 `file_unique_id` |
| `private_chat` | 私聊消息，直接忽略 |
| `command` | 以 `/` 开头的命令文本 |
| `unsupported_type` | 音频、贴纸、语音、位置、联系人，或没有任何可提取文本的富文本消息等未参与检测的内容 |
| `no_message` / `no_chat` / `no_sender` | Telegram 更新缺少消息、chat 或发送者，安全跳过 |
| `processing_error` | 读取设置、忽略名单或写入去重数据时出错；原有错误日志仍会输出 |


数据保留：默认保留 **180 天**，可通过 `DATA_RETENTION_DAYS` 调整。程序启动时执行一次清理，之后每 24 小时执行一次：

- 删除 `created_at` 早于保留期的 `forward_logs`；
- 先删除过期记录残留的流水，再删除 `updated_at` 早于保留期的 `forward_records`，避免孤儿流水；
- 删除不再被任何保留期流水引用的 `user_stats` 行（该表只含用户 ID）。

清理按批次执行，不会一次性锁住数据库。`/mars_rank all` 和 `/mars_me` 的“累计”只统计仍在保留期内的流水。

## 环境变量

| 变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `BOT_TOKEN` | 是 | 无 | Telegram Bot Token；未设置时程序启动失败 |
| `DB_PATH` | 否 | `bot.db` | SQLite 数据库路径；Docker 镜像内默认为 `/data/bot.db` |
| `DEDUP_SECRET` | 否 | 回退到 `BOT_TOKEN` | 文本去重 HMAC 密钥；更换后历史文本的重复记录将无法命中 |
| `STATS_TZ` | 否 | `Asia/Shanghai` | 排行榜周界使用的时区；时区名非法时回退到 UTC（`Asia/Shanghai` / `CST` 回退为固定 UTC+8） |
| `DATA_RETENTION_DAYS` | 否 | `180` | 数据保留天数；非法或非正数回退到 180。启动时清理一次，之后每 24 小时清理 |
| `PROXY_URL` | 否 | 无 | 访问 Telegram 的代理，支持 `http://`、`https://`、`socks5://`；格式无效或不支持的协议会被忽略 |

程序启动时通过 `godotenv` 读取工作目录下的 `.env`（如果存在），因此本地运行前建议从 `.env.example` 复制一份。

## 本地运行

要求 Go 1.26.1 或更高版本（以 `go.mod` 为准）。

```bash
cp .env.example .env
# 编辑 .env，至少填入 BOT_TOKEN
go run .
```

也可以先构建再运行：

```bash
go build -o mars-rescue-bot .
./mars-rescue-bot
```

数据库会创建在 `DB_PATH` 指定的位置（默认当前目录下的 `bot.db`），并自动建表。

## Docker 运行

镜像为多阶段构建：Go 构建阶段生成静态二进制，运行阶段使用 Alpine，并以非 root 用户（UID/GID `10001`）运行。镜像中不包含任何密钥，token 必须通过环境变量传入。

```bash
docker build -t mars-rescue-bot .
docker run -d \
  --name mars-rescue-bot \
  --env-file .env \
  -e DB_PATH=/data/bot.db \
  -v mars-data:/data \
  --restart unless-stopped \
  mars-rescue-bot
```

或使用仓库中的 `docker-compose.yml`：

```bash
docker compose up -d --build
docker compose logs -f
```

Compose 示例已经：

- 通过 `env_file: .env` 注入配置；
- 用 `environment: DB_PATH: /data/bot.db` 覆盖 `.env` 中的相对路径；
- 将命名卷 `mars-data` 挂载到 `/data`；
- 设置 `restart: unless-stopped`。

如果改用宿主机目录绑定挂载（例如 `./data:/data`），需要确保该目录对容器内 UID `10001` 可写：

```bash
mkdir -p data
sudo chown -R 10001:10001 data
```

`.env` 已被 `.gitignore` 与 `.dockerignore` 排除，不会被提交或打进构建上下文。

## BotFather 注意事项

机器人要读取群里的**全部**消息，否则隐私模式会让它只收到命令、@ 提及和回复：

1. 在 [@BotFather](https://t.me/BotFather) 中打开该 Bot，执行 `/setprivacy`，选择 **Disable**。
2. 修改隐私模式后，需要把 Bot **移出群再重新加入**，设置才会生效。
3. 或者把 Bot 设为群管理员——管理员 Bot 可以收到群内全部消息。
4. Bot 必须留在群内；管理员命令依赖 `getChatMember` 查询操作者权限。

## 已知限制

- **文本匹配不做模糊搜索**：归一化只处理全半角、大小写、空白、标点、零宽字符和 URL 追踪参数；同义词、错别字、语序变化仍会被视为不同内容。
- **仅覆盖文本、四种媒体与频道转发**：文本与图片/视频/动画/文件（含非频道转发），以及源为频道的转发会被去重；音频、语音、视频消息、贴纸、位置不参与。媒体去重只看 `file_unique_id`，重新压缩、截图、裁剪后的图片会被视为新内容；相册会拆成多条消息分别处理。
- **排行榜按出现次数计**：每一次出现都会计入排行榜，包括同一用户反复发送同一内容和自己重复。
- **冷却仅单实例**：冷却保存在进程内存中，重启后清零，也不会在多实例之间共享。
- **单实例 SQLite**：数据库连接数被限制为 1，设计为单实例部署；多个实例共享同一个 SQLite 文件不受支持。
- **忽略名单不支持 @username**：`/mars_ignore` 与 `/mars_unignore` 只接受“回复目标消息”或数字用户 ID。
- 私聊消息会被忽略；匿名管理员或频道身份发送、缺少发送者信息的消息会被跳过。
- 以 `/` 开头的文本不会进入去重流程。
